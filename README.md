## 1. 개요 (Overview)
본 과제는 스위치 4개의 입력만으로 피연산자와 연산자를 설정하고, 그 결과를 I2C 텍스트 LCD에 출력하는 계산기를 구현하는 것을 목표로 함. 상태를 유지해야 하는 입력 처리와 고정 폭 화면에 가변 길이 문자열을 출력하는 방법을 함께 다룸.

### 핵심 목표
* 스위치 4개의 폴링 입력 및 엣지 검출을 통한 1회 반응 처리
* 연산자 순환 및 피연산자 증감 상태 관리
* 정수 연산 결과의 범위 제한 및 예외처리
* 16칸 고정 폭 LCD에 가변 길이 문자열을 잔상 없이 출력

## 3. 하드웨어 구성 및 핀 맵 (Hardware Structure)

### Pin Configuration

```text
[ATmega128]                 [Target Component]
 PC0                 <-----   SW1 (피연산자 A 증가)
 PC1                 <-----   SW2 (연산자 변경)
 PD2                 <-----   SW3 (피연산자 B 증가)
 PD3                 <-----   SW4 (연산 실행)
 PD0 (SCL)           <---->   I2C Text LCD 16x2
 PD1 (SDA)           <---->   I2C Text LCD 16x2
```

### 주요 회로 특징
* **스위치:** 4개 모두 외부 10kohm 풀업 + 104(0.1uF) 커패시터 구조의 Active Low 회로
* **인터럽트 미사용:** LCD가 PD0, PD1을 TWI로 점유하므로 INT0, INT1을 사용할 수 없음. SW3, SW4만 인터럽트로 처리하면 스위치별 동작 방식이 달라져 코드 일관성이 떨어지므로, 본 과제에서는 4개 모두 폴링으로 통일함. 2일차 과제는 외부 인터럽트를 요구하지 않음
* **디바운스:** 하드웨어의 104 커패시터가 1차로 접점 떨림을 완화하고, 소프트웨어의 20ms 루프 주기가 2차로 걸러냄

## 5. 핵심 코드 및 레지스터 설정 (Key Implementation)

### 스위치 상태 수집 (hw3.c)
```c
uint8_t swRead(void)
{
    uint8_t sw = 0;

    if (!(PINC & (1 << PINC0))) sw |= SW1;
    if (!(PINC & (1 << PINC1))) sw |= SW2;
    if (!(PIND & (1 << PIND2))) sw |= SW3;
    if (!(PIND & (1 << PIND3))) sw |= SW4;

    return sw;
}
```
Active Low 회로이므로 논리 부정 연산으로 반전하여 눌린 상태를 1로 표현함. 두 포트에 나뉜 스위치를 하나의 비트 마스크로 모아 이후 처리를 단일화함.

### 엣지 검출
```c
now     = swRead();
pressed = now & ~prev;               // 안 눌림에서 눌림으로 바뀐 것만 남김
prev    = now;
```
현재 상태만 사용하면 스위치를 누르고 있는 동안 루프마다 값이 계속 증가함. 직전 상태와 비교하여 변화 시점만 추출하면 1회 입력에 1회만 반응함.

### 연산 및 예외처리
```c
switch (opIdx)
{
case 0:  c = (int16_t)a + b; break;
case 1:  c = (int16_t)a - b; break;
case 2:  c = (int16_t)a * b; break;
default: c = (b != 0) ? (int16_t)(a / b) : 0; break;
}
```

| 항목 | 처리 내용 |
| :--- | :--- |
| 자리수 초과 | A, B가 99를 넘으면 1로 순환. 최장 출력인 99 곱하기 99 의 결과 표시가 14칸으로 16칸 이내 |
| 음수 결과 | 뺄셈 결과가 음수일 수 있어 int16_t 사용. 곱셈 최대 9801도 범위 내 |
| 0 나누기 | B는 1부터 시작해 0이 될 수 없으나, 동작 예측이 불가능하므로 방어 코드 배치 |
| 정수 나눗셈 | 몫만 표시됨. 소수점 표시는 요구사항에 없어 미구현 |

### 고정 폭 출력
```c
void lcdLine(uint8_t line, char *str)
{
    char buf[17];
    uint8_t i = 0;

    while (i < 16 && str[i]) { buf[i] = str[i]; i++; }
    while (i < 16)           { buf[i] = ' ';    i++; }
    buf[16] = '\0';

    lcdString(line, 0, buf);
}
```
결과 자리수에 따라 문자열 길이가 달라지므로, 짧은 문자열만 쓰면 이전 글자가 뒤에 남음. 16칸을 공백으로 채워 한 행을 통째로 덮어쓰도록 처리함.

## 6. 동작 설명 및 결과 (Results)

### 동작 시나리오
1. 전원 인가 시 스위치 4개를 입력으로 설정하고 I2C LCD를 초기화함
2. 초기 상태의 수식을 LCD 1행에, 이니셜을 2행에 출력함
3. SW1 입력 시 A가 1 증가함 (99 초과 시 1로 순환)
4. SW2 입력 시 연산자가 더하기, 빼기, 곱하기, 나누기 순으로 순환함
5. SW3 입력 시 B가 1 증가함
6. SW1 부터 SW3 입력 시 결과 자리는 물음표로 유지되며 수식만 갱신됨
7. SW4 입력 시 연산을 수행하고 결과값을 표시함

```text
+----------------+
|12 * 7 = 84     |
|LDY             |
+----------------+
```

### 검증 과정에서 확인한 사항
과제 2에서 LCD 드라이버를 확보한 상태였고 스위치 폴링도 1일차에서 다룬 방식이므로 하드웨어 측 문제는 발생하지 않음.

다만 초기에 드라이버를 구현부와 선언부로 분리하여 작성한 결과, Makefile 없이 소스 하나만 컴파일할 경우 lcdInit 함수를 찾지 못하는 링크 오류가 발생함. 채점 환경에서 소스 파일 하나만 빌드할 가능성을 고려하여, 구현 전체를 static 함수로 헤더에 포함시키는 방식으로 변경함. 이후 Makefile, VS Code 태스크, 수동 명령 세 가지 경로 모두에서 빌드를 확인함.
